# 0.1.6 开发交接

日期：2026-10-27。基于已交付的本机 0.1.5 源码复制，在新的独立任务目录完成串行多文件导入。没有复用旧开发目录，没有推送 GitHub、安装插件、操作真实 Figma 文件或修改系统安全设置。

## 本次结构

- `src/queue.ts`：只做 File 元数据检查、安全显示名、重复名编号和轻量队列项。上限仍为 1,500,000,000 字节；不读文件字节。
- `src/ui.ts`：只预解析第一份有效文件供检查，其余惰性读取；一次 start 顺序完成读取、字体确认、转换、资产发送、宿主导入和清理。queueRunning/isBusy 防重复启动。success 释放 File 句柄，failed/cancelled 保留可重试句柄。
- 文件完成时清除 source、inputFile、BridgeDocument、中间任务引用；报告只保留精简元数据、计数和最多 100 条每文件提示，不持有源树或像素。字体目录和本批确认映射保留。浏览器 GC 与 Figma 的图像缓存不受插件强制控制。
- 首次启动快照还原选项，批次中途停止／重试继续沿用，并锁定选项；清空或重新选择批次后可修改。
- 新缺失字体暂停待确认，已确认映射在同批复用。首份 Auto 继续使用原 importer 的选择逻辑；成功后可从宿主实际 missingFonts 记录其替代结果供后续复用。
- `src/code.ts`：协议升级到 3，单一活动 session。begin/cancel 必须携带 clientId 和递增 sessionSequence；每次尝试生成新 session ID 和序号。clientId 在插件本次打开期间固定。highWater 阻止旧 begin 重放，128 条终态缓存只持有小摘要。淘汰的旧取消回执返回 unknown，而不谎报取消。
- cancel ACK 只在真正完成／失败回滚／取消后给 terminal:true。失败回滚或未知状态给 terminal:false，UI 锁定，不开始下一文件。成功提交后迟到 cancel 返回成功，不删除已成功画板。回执发送失败也不改变已提交状态。
- begin 带 batchId，宿主首次固定目标 PageNode。用户运行时切页不改变批次落点；页面删除会明确失败。文件名安全化、重名编号、按已有内容边界右侧追加。
- `src/importer.ts` 仅增加目标页／根画板名称／提交回调、边界布局及回滚残留确认。图层、文字、蒙版、图片转换算法沿用 0.1.5。无额外对比画板。

## 取消与不确定状态

取消当前继续下一项；停止全部取消当前和尚未开始项，已成功内容保留，随后可继续未完成项或清空新选。预解析中 × 清除会作废旧回调，但保持读取锁，直到未中断的 arrayBuffer／同步解析返回后才解锁。

网络式宿主通信超时、内存不足会暂停，回滚终态无法确认会锁定。不要将超时等同“未创建任何节点”。用户应先核查画布；若无法确认宿主状态，关闭插件再开启，不盲目重试结果不确定文件。

pagehide 仅尽力请求停止并禁止下一项，不代表关闭 Figma 后还能处理，也不能保证关闭瞬间回滚。正常关闭流程是先停止全部，等终态，再关闭。
