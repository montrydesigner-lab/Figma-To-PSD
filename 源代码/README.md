# Montry · PSD / PSB Bridge 0.1.6

一次拖入或多选多个 PSD / PSB，以并发度 **1** 的队列逐个导入 Figma。插件面板保持打开时自动处理；关闭插件或 Figma 后不会继续后台运行。

此版基于已经交付的本机 0.1.5 源码，在独立任务目录开发。保留原转换效果、可编辑图层、图片／蒙版／文字像素备份、源多画板、字体搜索、× 清除及隐藏层设置。仍然不生成额外「原始合成预览」对比画板。原 0.1.5 ZIP 和源码保持不变。

文件在插件内解析，不需要 AI、API Key 或外部解析服务。导入后，转换得到的图层和图片写入当前 Figma 文档；manifest 的网络域仍为 none。

## 安装

1. 关闭旧插件，完整解压 ZIP。
2. Figma 桌面版 → Plugins → Development → Import plugin from manifest…，选择解压目录根部的 `manifest.json`。
3. 打开插件后核对 LOCAL / 0.1.6，连接诊断中的 UI 与主程序均为 0.1.6。
4. `dist` 必须与 manifest 一同保留；安装已编译插件不需要 Node.js。

这是本地开发插件包，不会更新账号中的在线旧插件。本任务未替用户安装插件或修改任何真实 Figma 文件。

## 多文件操作

1. 一次拖入多个文件，或点击选择框多选 `.psd`、`.psb`、`.zip`。每个 ZIP 内仍只允许一个 PSD / PSB。
2. 文件先做扩展名、空文件和大小检查；只解析第一份有效文件供检查。剩余文件等待运行时逐个读取，不预读整批。
3. 检查还原选项和第一份文件的字体，启动队列。选项在本轮运行期间固定；队列显示各文件名、状态、总进度及当前文件进度。
4. 本批已确认的源字体映射会复用。后续文件出现新的缺失字体时暂停，请在原有搜索／选择控件中确认后继续。字体搜索支持中文、字体族与字重；清除搜索不会清掉当前选择。
5. 单个损坏文件或转换失败会记录错误并继续下一份。结束后可下载精简批次报告；重试失败项仅重新处理失败文件，不重复导入已经成功的文件。

每份文件创建独立的「文件名 · 可编辑」画板；重名会编号，按已有内容右侧追加，不覆盖先前画板。文件内部的多个源画板保持原有结构。一个批次固定导入目标页面；运行中切页不会使后续文件落入其他页面。

## 取消、清空和恢复

- **取消当前**：停止当前文件；若已经开始创建节点，等待本文件回滚终态确认后才继续下一份。已经成功提交的文件保留。
- **停止全部**：取消当前文件并取消所有尚未开始的文件。已成功导入的文件保留；重新选择文件可开始新批次。
- **× 清除**：清空插件中的队列、统计、映射／搜索和报告，不删除原文件或已导入图层。正在导入时禁用；预读取中清除会等待该读取结束后解锁，避免两次大文件读取重叠。
- **通信／回滚不确定**：队列暂停，不会自动开始下一项。不要假定当前文件没有写入；按界面提示确认宿主终态。无法确认时关闭插件并检查当前画布，再重开处理。
- **关闭插件**：不是一个可等待回滚的正常取消入口。请先停止全部并等待终态，再关闭。浏览器关闭通知尽力发出停止请求，但关闭会中断执行，无法保证收到最终回执；不要因此自动重试一个结果不确定的文件。

读取开始后的 `File.arrayBuffer()`、同步解压或解析不能立即中断。取消会在下一次可执行检查时生效；队列必须等当前操作释放后再启动下一份。取消仅回滚当前创建的节点；Figma 已上传图片缓存由 Figma 管理。

## 文件大小与内存限制

每个源文件和 ZIP 内选定 PSD / PSB 的上限保持 **1,500,000,000 字节**。这是本插件保护阈值，不保证低于 1.5 GB 一定成功。没有承诺无限文件数或固定安全批量。

每份文件仍完整读取并解析，图层解码还需要 RGBA、PNG 编码及消息中间数据；例如 10,000×10,000 的 8 位 RGBA 单层仅像素就约 400 MB。2048×2048 图片分块发生在图层解码之后，不是流式读取。单个解码图层上限仍为一亿像素。

完成每个文件后释放可释放的解析树、源字节和转换结果引用，只保留 File 引用及精简摘要供状态／重试使用；不能强制浏览器即时 GC。Figma 实际画布节点、图像缓存和已导入内容持续累积，长队列仍可能耗尽内存。内存错误、通信失联或回滚无法确认时暂停，而不是无限继续。

## 转换规则与边界

| 内容 | 处理方式 |
|---|---|
| 整体画布、源画板 | 保持 PSD 像素宽高、相对位置及画板裁切 |
| 分组、名称、显隐 | 重建图层树，默认跳过隐藏内容，可选择保留 |
| 文字 | 原生可编辑 Text / TextPath，尽量映射字体、字号、颜色、字距、行距、分段样式和旋转 |
| 图片、智能对象 | 使用 PSD 图层缓存生成无损 PNG，保留当前画面像素尺寸 |
| 超大图片 | 完整解码后按最大 2048×2048 分块，组合成图层容器 |
| 蒙版、剪贴和效果 | 沿用 0.1.5 的映射及近似规则，兼容性记录保留在摘要中 |
| 文字像素备份 | 默认保留隐藏备份 |
| 额外合成对比画板 | 不创建；视觉复核使用原 PSD / PSB |

Figma 没有 Photoshop 智能对象。导入图片可以移动、缩放、替换，不能双击编辑嵌入母版或智能滤镜。复杂字体度量、竖排、非等比文字变形、混合模式、调整图层、斜面浮雕、图案、发光和某些蒙版效果仍可能不同；不保证逐像素一致。8 位 RGB 是主要目标；支持的 16/32 位输入转换为 8 位 PNG，CMYK / Lab 需要先转 RGB。

批次报告刻意不保留完整源图层树、图片字节或全部节点 ID，以减少跨文件引用。摘要包含结果、错误、计数与有上限的兼容性记录；需要逐层视觉核对应使用源文件与 Figma 内容。

## 开发与验证

需要 Node.js 20 或更高版本，依赖版本未更换。

```bash
npm ci
npm run typecheck
npm run build
npm test
npm run test:ui
npm run test:queue-ui
```

浏览器测试需要 Playwright 及 Chromium。可通过进程环境变量 `CODEX_PRIMARY_RUNTIME_NODE_MODULES` 指向已有 Playwright 所在的 node_modules，通过 `PSD_UI_CHROMIUM_PATH` 指定 Chromium / Edge 可执行文件。测试仅使用合成小样例和模拟 Figma 宿主，不自动读取用户设计文件。

`src/ui.ts` 管理队列和面板通信；`src/code.ts` 管理单一活动会话、终态和目标页；`src/importer.ts` 创建图层并回滚当前文件；`pipeline.ts`、`normalize.ts`、`raster.ts` 等转换模块继承 0.1.5。

本次具体执行结果见 `TEST_REPORT.md`，后续开发与验收见 `HANDOFF-0.1.6.md`，第三方许可证见 `THIRD_PARTY_LICENSES.txt`。真实 Figma 渲染验收、真实大文件与长队列压力测试未执行。
